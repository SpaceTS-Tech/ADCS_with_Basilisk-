1.0 Purpose and Scope

This document defines the test cases used to verify the ADCS flight software mission modes. Each case runs the real compiled controller (ADCS_Software_v1.dll) at the 0.05 s control rate against a simulated plant, making this a software-in-the-loop (SIL) activity.

Out of scope

Not coveredReason
Vizard rendering and image decodeOptical cases use an analytically projected camera feed
Sensor noise, bias, misalignmentNo sensor models implemented; controller is fed truth state
Flight toolchain / target hardwareHost-compiled x86-64 GRT build with instrumentation
Disturbance torquesDrag, SRP, gravity gradient, residual dipole all disabled

2.0 Verification Method

Each test case declares which of the four verification methods it applies, in increasing order of rigour:

MethodDefinition
InspectionNon-destructive examination of the product. Here: reading generated C, parameter values and configuration.
DemonstrationOperating the product as intended and observing the expected result. Here: running a mode and confirming it behaves qualitatively.
TestControlled, predefined inputs producing a specific predefined output. Here: fixed initial conditions with numeric pass thresholds.
AnalysisModels, calculations and extrapolation from measured results. Here: settling time, damping ratio and momentum budget derived from recorded telemetry.
Verification - are we building the product right? Checks the implementation against the design.
Validation - are we building the right product? Checks that the end product meets the mission need. These cases are verification; validation against mission need is a separate activity.

3.0 Initial-State Definitions

Every test case records the state the satellite is in when the scenario starts. The terms are defined here so a case is reproducible from its label alone.

3.1 Attitude / body-rate state

StateDefinitionSet by
TUMBLED Body rate significantly above the control deadband; the vehicle is rotating uncontrolled. omega_BN_BInit non-zero
DETUMBLED Body rate at or near zero; attitude is controllable. omega_BN_BInit = 0
OFF-POINTING Detumbled, but attitude deliberately rotated off the nominal reference so the mode must acquire. sigma_BNInit rotated

3.2 Reaction-wheel momentum state

StateDefinitionThreshold
SATURATED Stored wheel momentum at or above the desaturation entry band; the controller must desaturate before it can point. |h| ≥ 0.95 × h_max = 47.5 N m s
DESATURATED Stored wheel momentum below the desaturation exit band; full control authority available. |h| ≤ 0.25 × h_max = 12.5 N m s

h_max = 50 N m s per wheel (CONTROLLER_H_MAX). Wheel momentum h = I_RW × omega_RW with I_RW = 0.0796 kg m^2.
